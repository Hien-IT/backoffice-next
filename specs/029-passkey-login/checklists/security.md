## Đăng ký và quản lý

- [x] CHK016 Đăng ký có yêu cầu nhập lại mật khẩu, và có nêu trường hợp user local không có mật khẩu (null) không? [Edge
  Case, Spec §FR-011]. **Phát hiện**: user local không có mật khẩu chưa được nói. Sửa: Edge Cases thêm: không thêm được
  passkey (xác nhận mật khẩu thất bại) như bật TFA; admin đặt mật khẩu trước.
- [x] CHK017 Spec có loại trừ rõ việc admin thêm hay đổi tên hộ, ở cả giao diện lẫn API không? [Completeness, Spec
  §FR-018, §FR-020, Contract api.md]. Đạt: API chỉ có đăng ký dưới `users/me`.
- [x] CHK018 Yêu cầu 403 theo provider có tách rõ endpoint của chính mình và endpoint admin xem user khác không? [Clarity,
  Spec §FR-016, Contract api.md]. **Phát hiện**: FR-016 nói "API đăng ký/quản lý trả 403 cho user provider khác default"
  trong khi contract cho admin `GET /users/:pk/passkeys` trả `[]` với user đích không phải `default`. Sửa: FR-016 ghi 403
  áp cho người gọi các route `users/me/*`; route admin trả danh sách rỗng với user đích không phải `default`.
- [x] CHK019 Spec có nói xóa passkey có kết thúc các session đã tạo bằng passkey đó không? [Gap, Exception Flow].
  **Phát hiện**: không. Sửa: Assumptions + Edge Cases: không (session không lưu passkey nào tạo ra nó); muốn thu hồi phiên
  thì đổi mật khẩu hoặc trạng thái user (cơ chế có sẵn xóa session). Cần chủ dự án xác nhận ở analyze.
- [x] CHK020 Giới hạn 10 passkey có được áp ở cả giao diện và API, với lỗi xác định không? [Completeness, Spec §FR-014,
  Contract api.md]. Đạt.
