# Interface and display fixtures (feature 013)

Fixture set of `specs/013-interfaces-displays` (data-model §6, FR-100): field configuration, relations, items and files
written by a real API, exported as a normalized snapshot that the component tests load (`src/test-utils/fixtures.ts`,
`mockFixtureApi` in `src/test-utils/fetch.ts`).

| File                     | Role                                                                              |
| ------------------------ | --------------------------------------------------------------------------------- |
| `seed.mjs`               | deletes then recreates the fixture set through the REST API (idempotent)          |
| `export.mjs`             | writes `snapshot/*.json` from the same API, normalized                            |
| `lib.mjs`                | arguments, REST client, test users                                                |
| `snapshot/`              | committed snapshot; `expected.<interface>.json` files are hand-written and kept   |
| `snapshot.test.ts`       | every interface and display id of `directus-registry.json` is used by a field     |
| `directus-registry.json` | interface and display ids with their option keys (generated by T011, do not edit) |

## Run

Against the `app` profile of `tests/parity` (Directus 11.17.4 on Postgres with PostGIS):

```sh
pnpm nx run web:fixtures -- --api http://127.0.0.1:8155 --email admin@example.com --password password
# or with an admin token
pnpm nx run web:fixtures -- --api http://127.0.0.1:8155 --token <admin token>
```

Each script also runs alone: `node fixtures/interfaces/seed.mjs --api ...`,
`node fixtures/interfaces/export.mjs --api ... [--out <dir>] [--kind directus|backoffice]`. Running both twice gives
byte-identical files (`meta.json` holds the UTC date of the export).

The seed only touches what it owns: collections `bo_*` (and their relations), folder `bo-fixtures` and its files, flow
`bo-flow`, roles, policies and users `bo-editor` / `bo-viewer`. `geometry.*` fields (`bo_std.map_point`, `map_polygon`,
`map_geometry`) are created only when the database accepts them (Postgres with PostGIS); otherwise the seed prints
`Refused: ...` and leaves them out.

## Snapshot files

`collections.json`, `fields.json`, `relations.json` (bo*\* only), `collections.system.json` and `fields.system.json`
(`directus_files`, `directus_folders`, `directus_users`, which bo*_ fields point at), `items.<collection>.json`
(`fields=_._`), `files.json`(folder`bo-fixtures`), `flows.json` (`bo-flow`, fields of the flows store), `permissions.<user>.json` (`/permissions/me`), `users.json` (`/users/me?fields=_,role.id,role.name`and`/policies/me/globals`per user),`meta.json`
(API kind, version, export date, geometry support).

## Normalization (export.mjs)

- every uuid (ids, foreign keys, uuids inside strings such as `/assets/<id>`) becomes `bo-<n>`: admin, folder, files (by
  title), flow, then policy, role and user of `bo-editor` and `bo-viewer`, then `bo_m2a_b` rows (by title), then in
  order of appearance; `FIXED_UUIDS` of `lib.mjs` are data and stay;
- integer keys stay numbers (tables are recreated, so they restart at 1);
- `date_created`, `date_updated`, `user_created`, `user_updated`, `created_on`, `modified_on`, `uploaded_on`,
  `filename_disk`, `last_access`, `last_page`, `meta.id` become `null`; argon2 hashes become one fixed string;
- `/permissions/me` keeps `bo_*` and `directus_*` collections only (the database is shared with other suites);
- rows are sorted by primary key (`bo_m2a_b` by title), item keys follow `fields.json` order.
